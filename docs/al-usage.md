# My Personal Al Usage Rules

## Rule 1 - What I will never paste

I will never paste passwords, API keys, tokens, `.env` contents, personal data, customer data, proprietary material, or unredacted production logs into an Al tool. I will remove private paths, identifiers, and configuration values from error reports before sharing excerpts.

## Rule 2 - What I will always verify before accepting

I will verify Al-generated code and advice against the project documentation and source code, understand the relevant changes, run the appropriate tests, and check for security, correctness, and unintended side effects before accepting it.

## Rule 3 - How I will record Al contributions

I will record what Al helped produce, the prompts or inputs at a useful summary level, the files or decisions affected, and the checks I performed before I accepted the result. I will clearly distinguish Al suggestions from my own review and final decisions.
