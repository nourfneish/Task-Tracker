Where AI helped: I used Cursor for the initial build: drafting the search/filter query logic and endpoint on the backend, and the filter bar and activity panel on the frontend. I used Claude for the verification pass — reading the existing repo, running pytest and curl directly via its bash tool, and debugging from actual tracebacks rather than guesses.

Where it slowed things down: Cursor's autocomplete kept suggesting a second assignee filter block further down in main.py as I was typing the frontend fetch logic, which is likely how the duplicate-route situation crept in in the first place — accepting a plausible-looking multi-line suggestion without scrolling up to check it wasn't already handled above. Also when not explicity asked to not create new files cursor was creating files that already existed (as main.py)

Where my review changed the result: The Claude's default fix for the duplicate-route bug was to keep the first (unvalidated) definition and delete the second, since it appeared first and "worked" in the sense of returning 200s. I rejected that — validate_status_transition exists specifically to enforce the state machine, and silently accepting invalid transitions defeats it. I had it keep the validated version instead and delete the dead one, then reran the transition tests to confirm 422 came back correctly.
